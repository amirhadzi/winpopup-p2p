WinPopup P2P 0.3.1 — verification record
Date: 1 October 2026

BUILD-PATH PRIVACY FIX
- The prior 0.3.0 executable contained 23 private build-path strings from
  Tox diagnostics. A clean dependency/application rebuild remaps those
  paths to relative deps/ and app/ paths at compilation, preserving useful
  diagnostics. No binary string patching is used.
- The new executable has no builder username in narrow or UTF-16 strings,
  and passes the mandatory user-profile/source/build-root scan.
- The same check rejects the actual old 0.3.0 release binary.
- 32 scanner regression checks pass, including narrow/wide encodings,
  both byte alignments, separator variants, and a custom CI build root.
- Locally built static libraries are omitted from the source ZIP because
  intermediate compiler/archive metadata can retain build directories.
- All six suites pass: the existing 173 functional checks plus 32 scanner
  checks. Previously distributed files are unaffected by this update.

BUILD
- Native Windows x64 Release executable, MSVC 2022, static C/C++ runtime.
- PE machine: 8664 (x64), Windows GUI subsystem.
- ASLR, high-entropy addresses, NX and Control Flow Guard enabled.
- Imports only Windows system libraries; no external runtime DLLs required.
- Tox 0.2.23 with the included idempotent-cancellation patch; libsodium
  1.0.22, pthreads4w 3.0.0, and Nayuki QR Code generator 1.8.0.
- The dependency build verifies upstream archives, the local patch, and
  Messenger.c hashes before and after patching. Fresh patch application
  and idempotent reapplication passed. Rebuilt dependencies passed
  encrypted-save and Tox lifecycle smoke tests.

CORE INTEGRATION: 36 CHECKS PASSED
- Separate encrypted profiles and unique valid Tox identities.
- Real Tox friend request over loopback UDP; explicit contact acceptance.
- Direct connectivity, bidirectional Unicode text and delivery receipts.
- Display-name propagation and persistence.
- Oversized/offline sends fail without false delivery.
- Corrupt invitations and unrelated URLs are rejected.
- Malformed incoming UTF-8 is safely replaced for display.
- Standard toxEsave encrypted profile format.
- Wrong passwords/corrupt profiles preserve the existing identity.
- Simultaneous profile opening is rejected.
- Identity and contact changes survive restart.

FILE INTEGRATION: 39 CHECKS PASSED
- Two real Tox peers with disposable encrypted profiles on loopback.
- Multi-chunk binary files, PNG images and empty files arrive byte-for-byte.
- Unicode filenames and paths, authenticated contact-key binding, unique
  local tokens, and rejection of a mismatched intended recipient.
- No download writes before acceptance; explicit decline/cancellation.
- Existing destinations are preserved; invalid destinations fail safely.
- Cancellation cleans partial data without publishing incomplete files.
- Three back-to-back simultaneous-cancel/immediate-next-transfer cycles.
- Independent concurrent transfers and transfers in both directions.
- Missing/directory sources, unknown controls and the eight-transfer cap.
- Contact removal and shutdown clean up pending transfers.
- Receiver-owned native cancellation and a file-ID completion fence avoid
  reusing Tox slots while old controls remain in flight. Unsupported peers
  have a bounded handshake; unacknowledged cleanup blocks further files
  to that peer until reconnect, without blocking ordinary text chat.

LEGACY PEER INTEGRATION: 28 CHECKS PASSED
- A raw c-toxcore peer with no WinPopup capability extension connects over
  loopback. Unicode text and matching delivery receipts work normally.
- Unsupported outbound file negotiation fails after about 10 seconds,
  without sending a native file offer or any file data.
- Unsupported incoming offers are cancelled without exposing an Accept
  action, requesting payload data, or creating a file/partial download.
- Bidirectional text continues to work after both rejected file attempts.

INTERFACE AND QR
- 55 UI behavior checks passed with hidden production windows: the
  existing 36 message/draft/receipt/recipient checks, plus 19 file-transfer
  controls, history, identity snapshots, and QR bitmap-format checks.
- 15 QR checks passed: canonical full tox: invitation, checksum validation,
  input rejection, module bounds, geometry, normalization and quiet zone.
- Independent OpenCV decoding recovered the exact 80-character invitation
  from two QR encoder fixtures and from all six displayed/copied QR
  fixtures at 96/120/144 DPI.
- 27 GDI fixtures cover main, Send Message, reference arrangement, setup,
  invitation/clipboard QR, and offered/progress/saved transfer states at
  96/120/144 DPI. Native controls passed text/masking/button-state checks.
- Native startup/shutdown smoke test passed.
- The classic dimensions remain: main 350 x 284 and Send Message 308 x 298
  logical pixels. New dialogs follow the same classic drawing style.
- These fixtures are offscreen test renders, not live-conversation desktop
  screenshots. Some native non-client details such as scrollbars can be
  omitted by offscreen rendering. Artwork is an independent recreation.

COMPATIBILITY AND SOURCE
- Identity/profile format remains compatible with 0.1.0, 0.2.0 and 0.3.0.
- File sharing requires WinPopup 0.3 or later at both ends. Text remains
  compatible with ordinary Tox clients.
- The source package includes application/tests, QR sources, pinned native
  dependency archives, the local Tox patch, build scripts and license texts.

LIMITATIONS
This is an unsigned development build without an independent security
or interoperability audit. Automated end-to-end transfer tests used local
UDP peers; file transfers across independent internet connections,
restrictive NATs and relay-only networks have not been tested here.
Public Tox discovery succeeded on this host during earlier 0.2.0 testing.

Images use the same file-transfer path; there is no inline image viewer
or camera QR scanner. Both people must remain online. No interrupted-file
resume, persistent chat/transfer history, voice, video, group chat, or
offline store-and-forward messaging is implemented. Saved downloads are
ordinary files, outside the encrypted portable identity profile.
